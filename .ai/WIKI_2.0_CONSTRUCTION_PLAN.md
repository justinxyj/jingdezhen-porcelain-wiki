# Wiki 2.0 全站改造施工清单

更新时间：2026-09-19
基准：当前 main
目标：依据《Wiki 2.0 最终信息架构蓝图》，把现有 MkDocs + JS + Supabase 数字博物馆从“栏目集合”改造成“知识世界 + 数字博物馆工具 + 知识网络”的统一产品。

## 0. 施工原则

- 不先删旧页面；先建立新入口，验证内容可达后再清理旧入口。
- `entries.category` 继续作为数据库实体类型，不强行改成七大知识世界。
- 统一知识节点入口继续使用 `/entry/?slug=...`。
- 七大知识世界是用户认知层；数字博物馆是工具层；知识网络是关系层。
- 任何新关系、事实和媒体必须有来源或明确标记为待核验。
- 每个阶段都必须通过 MkDocs strict、类型检查、runtime smoke、Pages browser smoke。
- 每批改造尽量形成独立 commit/PR，便于回滚。

## Phase 4E-5 Deepening — 2026-09-20
下一层知识链固定为：

**材料 → 器物 → 时代 → 窑址 → 人物**

设计原则：
- 材料先作为 canonical 工序字段的可解释线索，不建立未经来源支持的独立材料节点。
- 器物、人物、窑址、文献必须从已有 Entry 事实关系进入。
- 时代沿用统一 eraGroup，不创建第二时代体系。
- 窑址沿用 Entry map metadata，不复制一套空间数据库。
- 人物沿用 Entry relations，不因“某工序与人物职业相关”而自动推断人物关系。
- 只有真实关系存在时才继续全球网络；全球网络不反向生成事实关系。
- 本阶段优先完善产品链路，再进行高价值工艺关系深审。


## Phase 4E-5 Craft Relation Deep Audit — 2026-09-20
工艺关系从“全流程覆盖”进入“证据关系”阶段。

审查规则：
1. 不因某历史时期存在制瓷业，就把全部 72 道工序挂上该历史条目。
2. 不因器物属于陶瓷，就自动挂到所有工序；必须有工艺说明。
3. 不因人物是陶瓷人物，就自动挂到工序；必须有公开技艺/职业/实践证据。
4. 窑址必须有明确生产空间、窑具、烧成或工序考古/制度证据。
5. 每条新增关系保留来源元数据。
6. 工序关系属于知识图谱/探索层；不得绕过 Phase 3B A+ / A recommendation gate。
