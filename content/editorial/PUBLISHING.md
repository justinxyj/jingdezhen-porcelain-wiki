# 安全发布与状态记录

本轮编辑稿默认未应用。数据库发布与 GitHub Pages 部署是两个独立状态，网页上线不代表数据库文案已经更新。

## 当前发布入口

`scripts/publish_editorial.py` 与 `Editorial content release` 手动工作流仅更新清单中的 79 条公开条目、65 道已审定工序和 16 个时间轴语境；7 个术语待考记录不在发布目标中。连接通过 `H3_DB_URL` 或本地 `DATABASE_URL` 安全配置，禁止把密钥写入仓库、日志或聊天。

1. 先运行目录安全边界探针和离线发布边界测试。
2. 不带 `--apply` 执行真实连接预演。事务锁定目标，逐项核对版本和原始内容哈希；任何变化使整批停止。预演执行更新及读回校验，最终回滚。
3. 检查受保护输出目录中的 `backup.json`、`diff.json` 和 `receipt.json`。备份包含目标更新前完整记录；不得把备份提交到公开仓库。
4. 审核 diff 后，使用预演 receipt 的 `preview_sha256` 执行 `--apply --preview-sha256 <摘要>`。重新读取并校验全部记录；预演后有任何目标变化，摘要校验失败，整批不提交。
5. 写入成功后在独立事务读回所有更新字段。时间轴编辑综述使用 `ai_summary` 与明确的 `editorial_synthesis` 类型，保留机构原文列；普通参考资料不会获得自动核验标记。
6. 重新生成静态条目、部署 Pages，并从生产 REST 与生产页面核对 79 / 65 / 16 的真实内容。receipt 的 `website_verified` 默认 false，数据库读回不能代替网站验收。

## 恢复原则

保留原始备份、差异及提交收据。若提交前报错，数据库事务回滚；若提交后验证异常，先停止后续发布，保留备份和错误类别。恢复前锁定同一目标并逐字段核对当前值仍等于本次 diff 的 after；存在后来编辑时禁止覆盖。仅恢复本次变更字段，保留并检查触发器和版本规则。不要直接回放整行或降低版本号来覆盖新的编辑。

## 外部依赖

当前云环境没有写入凭据，现有 H-3 生产工作流日志确认 `H3_DB_URL` 未配置。因此离线快照身份与哈希校验不能称为生产 Dry Run，编辑稿不能计为 Production。连接配置后仍须完成上述真实预演、写入、读回及网页复验。
